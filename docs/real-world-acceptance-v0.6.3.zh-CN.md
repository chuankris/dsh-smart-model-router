# dsh-smart-model-router v0.6.3 真实场景验收

日期：2026-08-28

## 目标

本轮不再只验证“分类结果和预期一致”，而是从 DSH 页面发起真实任务，检查附件进入、模型选择、工具调用、最终答案和失败行为是否同时正确。

## 测试矩阵

| 场景 | 真实输入 | 预期 | 结果 |
| --- | --- | --- | --- |
| PDF 读取 | 含固定文本的标准 PDF | 提取 `DSH PDF ROUTER TEST 2026` | 通过 |
| 音频理解 | 含三位验证码的 WAV | 有 ASR 时转写；无凭证时快速、可行动地失败 | 通过安全失败 |
| 视频理解 | 2 秒纯蓝 MP4 | 回答约 2 秒、蓝色 | 通过 |
| 联网研究 | 查询当天 OpenAI 官方最新三条更新 | 官方链接、页面发布日期和排序均可核验 | 失败 |
| 图片生成 | 明确要求生成图片 | 选中原生图片模型并返回图片产物 | 受图片专用额度/运行时可用性阻塞 |

## 本轮发现和修复

### 1. PDF 后续调用触发空决策崩溃

DSH 会把 Auto 虚拟路由替换成上一次的具体模型头。路由器识别到这是同一条 Auto lineage 后会返回具体配置，但此时没有新的 `decision`。中间件仍读取 `decision.winner`，导致 `Cannot read properties of null`。

修复方式：具体 lineage 透传时直接返回模型配置，并记录 `lineage-pass-through`，不再进入依赖路由决策对象的日志分支。

### 2. “命中联网模型”不等于“联网答案正确”

测试确实命中了具备 grounding 能力的 Gemini 路径，并执行了多轮搜索，但最终把搜索摘要中的候选页面错误归因为“当天发布”。官方页面实际日期为：

- `The Hugging Face incident and the road ahead`：2026-08-26。
- `Disrupting a new covert influence campaign from Russia`：2026-08-25。
- `Advancing price-performance for developers with GPT-5.6 in Kiro`：2026-08-24。

因此，本场景判定失败。以后联网研究必须把“任务分类正确”和“答案事实正确”分开计分。

## 正式验收标准

1. 分类验收：是否识别为 grounded research。
2. 能力验收：所选 provider 是否声明并实际具备联网/grounding 能力。
3. 证据验收：每个事实是否有可打开的第一方来源。
4. 日期验收：发布日期必须从正文元数据读取，不能由搜索摘要或结果顺序推断。
5. 排序验收：声称“最新”时必须展示用于排序的日期，并处理同日并列。
6. 成本验收：记录耗时、工具次数和 token；高成本错误答案必须判失败。
7. 失败验收：无法确认“今天有三条”时应明确说明数量不足，不能用更早文章补齐后仍称当天发布。

## 待优化

1. 在 grounded research 路径加入事实验收器，对 URL、发布日期、域名和排序声明做结构化检查。
2. 给时间敏感问题注入绝对日期和时区，避免“今天”在跨日任务中漂移。
3. 设置搜索步数、总耗时和 token 上限；达到上限后返回证据不足，而不是继续扩散搜索。
4. 将真实回答保存为 shadow 样本，分别标注分类、模型选择、事实性和成本。
5. 图片生成继续保持硬能力约束；专用额度不可用时快速失败，不回退到文本模型伪造成功。

## 自动化结果

- 单元/集成测试：35/35 通过。
- 基础路由基准：12/12 通过。
- v2 场景基准：6/6 通过。
- shadow 分类器评估：16/16 通过。
- 真实页面验收：PDF、视频通过；音频无凭证时安全失败；联网事实性失败；图片生成受外部容量阻塞。

| 1M tokens 中文知识库 | 运行时上下文未知仍选择 `kimi/kimi-k3` | 1 步失败关闭，明确没有模型声明 1M 上下文能力 |

### 新修复

1. 扩充中文生产风险信号：支付、财务、记账、资金、事务内幂等、重复回调、只记账一次、崩溃后恢复、故障恢复、数据一致性、权限、认证和漏洞。
2. DSH 上传路径同时支持绝对路径和 `.dsh-uploads/...` 相对路径，并允许扩展名后紧跟中英文标点。
3. `minContextTokens` 改为真正的硬约束：运行时不声明上下文窗口时判不满足；推荐结果无合格模型时禁止 legacy 猜测回退。

### 内容质量结论

- 火山批量推理 API 和 JSONL/TOS 任务流程有官方文档支持。
- 回答中的“价格通常约为实时接口的一半”没有在本轮官方材料中获得直接价格证据，应标记为待核验，不能作为正式成本承诺。
- Kimi 场景证明“provider 亲和”不能替代运行时能力声明；额度充足、provider 正确也不代表上下文窗口满足任务。

## v0.6.5 严格来源研究回归

- 真实复现：普通联网摘要由 Gemini 处理时，可能把第三方页面误报为官方来源；Claude Opus 4.6 在页面不可访问时也曾继续给出带近似日期的猜测。
- 路由策略：同时出现“官方/第一方/直接链接/发布日期/必须打开页面核对”等严格约束时，优先锁定 `codex-chatgpt`，并将其视为高可靠性任务；即使容量候选为空并进入 legacy fallback，也继续选择 `gpt-5.6-sol`，不降级到 Mini。
- 同轮稳定性：工具续步沿用首步 provider、model 与 reasoning effort，避免搜索过程中因上下文变化漂移到另一模型。
- 实测结论：GPT-5.6 Sol 在浏览器桥接不可用时能按要求停止，不根据搜索摘要编造；但浏览器桥接本身仍是外部依赖，路由只能降低幻觉概率，不能替代结果级事实校验。
- 验收准则：严格来源任务必须检查“选中了谁”“工具续步是否漂移”“页面不可用时是否停止”三项，不能只看最终文字是否流畅。

## v0.6.6 否定表达与引用隔离

- 发现方式：用“不要联网”“不要搜索”“把严格核验要求翻译成英文”“不要生成视频”等反向场景批量探测规则边界。
- 修复前风险：否定词、粘贴文本和引号内指令会被当成用户真实意图，造成无谓的 Codex 路由、工具要求或视频生成失败。
- 修复策略：硬规则与 shadow 分类器共享同一份清洗后的意图文本；路由前先清洗待翻译引用内容；显式否定联网时，不再让“今天/最新”等粘贴内容触发 grounding；视频生成使用与图片生成一致的否定意图过滤。
- 回归原则：每条正向能力规则至少配一条中文否定、一条英文否定和一条引用/粘贴污染测试；正向严格来源与视频生成仍必须保持命中。

## v0.6.8 配额失败策略遵循

- 真实故障注入：原生 `gemini-3.1-flash-image` 返回 `QUOTA` 后，容量反馈正确生效，下一轮能转为 Sol 工具辅助生成，并产出真实 PNG。
- 新发现：当用户明确要求“图片模型额度不可用就直接说明/停止”时，旧策略仍允许工具辅助降级，结果虽然可能成功，但违反用户指定的失败语义。
- 修复：将条件式“额度不可用就说明、报错、失败或停止”识别为禁止工具辅助 fallback；普通图片请求仍保留原生模型失败后通过能力模型调用图片工具的降级路径。
- 续问继承：以“再试一次/重试/try again”等开头的带约束续问，即使超过短句阈值，也继承上一轮任务类型，同时叠加本轮新的失败策略；避免被误降为普通文本后绕过约束。
- 验收要求：配额恢复测试必须同时检查 provider feedback、下一跳模型、是否生成真实 artifact，以及是否遵守用户对 fallback 的显式约束。

## v0.6.9 图片理解、编辑与变体

- 边界矩阵：分别测试纯图片理解、双图比较、修改已有图片、基于参考图生成变体、DSH 上传路径编辑、否定编辑后再正向生成，以及仅翻译图片生成指令。
- 修复前缺陷：编辑与参考图变体被误当成图片理解；“不要修改或生成”仍会触发工具需求；待翻译引用在扩展生成关键词后存在重新污染路由的风险。
- 修复：引用清洗前移并由多模态规则共享；检测真实图片输入或 `.dsh-uploads` 引用后的编辑/变体意图；否定修改动作不参与工具推断，但后续独立的正向生成意图仍然有效。
- 路由语义：看图与比较属于 `multimodal-understanding`；修改、变体和输出新图属于 `image-generation`，必须满足输入图片与生成输出两侧能力约束。
- 真实 M1 验收：Auto 正确识别 `.dsh-uploads\\blue-circle.png` 编辑任务；图片专用额度不可用后命中 Sol 工具辅助路径，先读取参考图再生成并校正尺寸，9 个续步无漂移，产出真实 `red-circle.png`。但人工视觉检查显示圆形偏洋红而非严格纯红，说明“artifact 存在、尺寸正确”不能替代颜色语义验收；该项记为执行/产物验证层待优化，不冒充路由层通过。

## v0.7.0 图片 Artifact 机器验收器

- 目的：不再把“模型声称已生成”“文件存在”或人工快速目测当作颜色与版式通过证据。
- 实现：`scripts/validate-image-artifact.mjs` 使用 Node 内置 PNG/zlib 解码，无第三方依赖；检查精确宽高、边缘背景色比例、主体覆盖率、目标前景色命中率和主体平均 RGB。
- 判定：每项检查独立输出布尔值与原始指标，任一失败时 CLI 返回非零退出码；颜色使用可配置 RGB 欧氏距离容差，透明像素按目标背景色合成后评估。
- 回归基线：纯 `#FF0000` 圆形通过；`#FF0070` 洋红替代品必须在前景色检查中失败，从而自动捕获 M1 人工发现的偏色问题。
- 范围：当前支持非隔行的 8-bit 灰度、灰度透明、RGB、RGBA PNG；复杂语义与参考图结构保真仍需视觉模型或专用评估器补充。
- 自动闭环：对具备“精确尺寸 + 白色背景 + 明确主体颜色”的本地 PNG 任务，插件在 `agent/turn-stopping` 自动验收；失败时通过 `agent.steer(...)` 注入一次带指标的修正要求，同一 turn 最多重试一次，第二次仍失败只记录事件，防止无限循环。
- 事件：通过与失败分别记录 `artifact-validation-pass` / `artifact-validation-fail`，包含路径、检查项和原始指标，便于 shadow 样本与后续用户反馈关联。
- 会话隔离：只扫描当前真实用户消息之后出现的本地 PNG 路径；历史 turn 的成功文件不能替代本轮 artifact，避免“本轮没有产物但旧图刚好通过”的假阳性。
- 分类一致性：硬规则确认图片编辑/变体属于生成后，shadow 分类器使用带 `image output` 的清洗意图，避免未来 classifier rollout 把编辑任务重新降回图片理解。
- 真实基线：早期蓝圆被界面宣称为 1024×1024，机器读取实际为 1254×1254；早期红圆虽为 1024×1024，但主体平均 RGB `[248,10,112]`、`#FF0000` 命中率为 `0`，因此明确失败。
- 真实通过：M2R/M4 在 Sol 工具辅助路径生成本地 PNG，`artifact-validation-pass` 记录 1024×1024、边缘背景比例 `1`、目标红色命中率 `1`、主体平均 RGB `[255,0,0]`；多步过程中路由保持 Sol。
