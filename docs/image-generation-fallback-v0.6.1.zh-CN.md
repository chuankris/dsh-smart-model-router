# 图片生成路由容错与验收（v0.6.1）

## 背景

DSH 页面曾出现两类图片生成失败：

- 原生图片请求报 `no registered model satisfies image-generation`。
- 普通图片请求报 `The operation was aborted due to timeout`。

这两个错误发生在模型真正执行之前，属于路由层缺陷，而不是图片供应商的额度或生成质量问题。

## 根因

1. DSH 启动或插件加载初期，`resolveModelInfo` 可能短暂返回空值。路由器此前把一次瞬时未解析直接当成模型永久未注册。
2. 容量推荐接口设置了超时，但图片生成与普通文本共用“失败关闭”策略。推荐超时时，即使用户允许工具，也不会切换到可调用图片工具的模型。
3. 执行策略没有真正尊重“不使用工具”指令，声明的 `allowToolAssisted` 与用户约束可能不一致。
4. 原测试只覆盖正常推荐和通用超时降级，没有覆盖图片生成的冷启动、工具许可和工具禁用组合。

## v0.6.1 修复

- 原生候选解析增加一次短间隔重试，吸收模型注册表冷启动抖动。
- 图片推荐超时或无可用原生候选时，若用户允许工具，选择已注册且工具能力较强的模型，进入 `agent-tool` 执行路径。
- 明确识别“不使用工具”等约束；禁止工具时不允许工具辅助降级。
- 决策记录新增 `tool-assisted-fallback` 来源与 `actualPath: agent-tool`，便于审计原生生成和工具生成。
- 原生模型存在但额度耗尽时，保留真实供应商错误，不伪装成路由成功。

## 回归测试

新增四个关键用例：

1. 明确禁止工具时，执行策略必须设置 `allowToolAssisted: false`。
2. `resolveModelInfo` 首次返回空值、第二次恢复时，仍应路由到原生图片模型。
3. 图片推荐超时且允许工具时，应选择工具辅助模型继续执行。
4. 图片推荐超时且禁止工具时，应快速返回包含用户约束的清晰错误。

完整自动化结果：

- Router 单元测试：28/28。
- 基础路由基准：12/12。
- 多模态与降级场景：6/6。
- 轻量分类器样本：16/16。
- Capacity 单元测试：16/16，构建成功。

## 真实 DSH 页面验收

环境：DSH Local Build `141eb6f`，Router `0.6.1`，`http://127.0.0.1:3080/`。

### 用例 A：原生图片且禁止工具

提示词：

```text
【T6F 图片快速失败】请生成一张蓝色方块 PNG 图片，不使用工具。
```

结果：成功路由到 `antigravity/gemini-3.1-flash-image`，最终返回 Antigravity `429 QUOTA`。这证明“模型未注册”缺陷已经修复，同时禁止工具约束得到保留。当前失败是精确模型额度耗尽，不是路由器失败。

### 用例 B：允许工具辅助生成

提示词：

```text
帮我生成一张猫猫图片
```

结果：原生图片模型进入额度冷却后，路由器选择工具辅助路径，调用 `image_generate`，41 秒内生成实际 PNG：

```text
D:\dsh\.dsh-rc8\plugins\subscriptions\images\image-2026-08-27T14-18-45-531Z-3vk7op-0.png
```

原页面中的路由超时未复现。

## 行为边界

- “禁止工具”表示只接受原生图片模型；原生模型额度耗尽时必须明确失败，不能偷偷调用工具。
- 未禁止工具时，工具辅助生成是可用性降级，不应宣称为原生模型生成。
- 工具辅助路径解决的是服务可用性，不代表所选工具模型一定具备最佳图片质量。
- Antigravity 的隐藏精确模型额度仍需运行反馈和冷却策略校准；共享额度充足不代表图片专用模型可用。

## 后续优化

1. 将工具辅助候选从通用质量排序升级为显式 `imageToolUse` 能力评分，避免仅凭综合质量选模型。
2. 为原生图片模型增加低成本、低频率的精确模型探针，并设置每日探针预算。
3. 在决策卡片中显著标记“原生图片”或“工具辅助图片”，避免用户误解执行方式。
4. 持续收集原生额度失败、工具生成失败和产物质量反馈，分别统计路由正确率与产物合格率。
5. 增加 DSH 启动后的冷启动端到端测试，覆盖插件刚加载时立即提交图片请求的场景。
