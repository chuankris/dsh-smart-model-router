# DSH 可解释动态模型路由 v0.5

## 目标

`dsh-smart-model-router` 的目标不是简单按关键词切换模型，而是在能力约束、实时额度、历史效果和用户反馈之间做可复盘的选择，并让每一次选择都能回答：

- 为什么选中这个模型；
- 为什么没有选择其他模型；
- 当前额度信息是否可靠；
- 规则路由与轻量分类器是否一致；
- 实际执行结果是否支持这次判断。

## 当前链路

1. DSH 会话选择 `dsh-auto/dynamic`。
2. 路由器从请求内容提取任务特征，例如编码、批处理、长上下文、检索、多模态理解、图片生成和视频生成。
3. 路由器向 `dsh-provider-capacity` 请求实时容量快照，并结合模型画像计算候选分数。
4. 硬能力不满足、额度处于冷却期或证据不足的候选会被拒绝。
5. 选中结果、贡献项、备选项、拒绝原因、额度状态和会话 lineage 被记录到统一评估数据。
6. 请求由 DSH 使用具体 provider/model 执行，结果与错误再回写到同一条评估链路。
7. 用户在“容量与路由”卡片上的正向或负向反馈被持久化，用于离线校准。

## 轻量分类器

v0.5 新增一个本地线性分类器，不调用额外大模型，不新增推理费用。它输出任务标签、置信度、边际值、候选标签和命中特征。目前支持：

- `general-text`
- `simple-text`
- `production-coding`
- `batch-coding`
- `long-context`
- `grounded-research`
- `multimodal-understanding`
- `image-generation`
- `video-generation`

分类器当前固定运行在 `shadow` 模式：结果进入评估数据和解释卡片，但不参与最终选型。这样可以先积累混淆样本、低置信度样本和规则分歧样本，再决定是否逐步放量。

## 数据闭环

统一评估记录包含四类信息：

- 模型画像：能力、上下文、模态、成本和可用 provider。
- 容量快照：剩余额度、冷却状态、更新时间和可靠度。
- 路由结果：选中模型、分数贡献、备选项、拒绝项、规则特征和分类器结果。
- 执行反馈：成功、失败、错误类型、用户评价和后续纠正。

离线校准使用这些记录搜索权重组合，当前保持“能力约束优先，容量与证据只做次级排序”的策略。任何分类器晋级都必须先通过固定评测集，再经过 shadow 数据验证，最后才允许小流量影响路由。

## 当前验收结论

- 路由单元测试：22/22。
- 传统基准集：12/12。
- v2 场景基准集：6/6。
- 分类器评测集：16/16。
- 真实 DSH 批量编码请求命中 `volcengine/GLM-5.3`，分类器旁路标签为 `batch-coding`，置信度约 93%。
- 跨 DSH 重启的 Auto lineage 可恢复，后续请求仍可从上一次具体模型重新进入动态路由。
- 图片生成实际请求正确命中 `antigravity/gemini-3.1-flash-image`，但 provider 返回隐藏图片额度 429，尚未取得图片产物。

## 后续优化

1. 累积真实 shadow 样本，重点观察低置信度、规则与分类器分歧及最终用户负反馈。
2. 将任务分类与模型质量拆开评估，避免“任务识别正确”被误当作“模型选择正确”。
3. 为隐藏额度 provider 增加分模型探针和更长冷却，减少总额度充足但专用模型不可用时的重复失败。
4. 分类器达到稳定门槛后，仅对高置信度、低风险任务提供小幅分数修正，不直接越过硬能力约束。
5. 引入时间衰减和样本量置信区间，避免少量历史成功长期支配路由。
6. 补齐图片生成真实产物验收，以及浏览器桥接恢复后的解释卡片像素级验收。
